Simulação em Python

Folha de consulta do solve_ivp aplicada a fermentação: assinatura, escolha de método, eventos, tolerâncias e as armadilhas que produzem gráficos convincentes e errados.

O esqueleto que sempre funciona

import numpy as np
from scipy.integrate import solve_ivp
import matplotlib.pyplot as plt

# 1. Parâmetros — com unidade em comentário, sempre
mu_max = 0.40   # 1/h
Ks     = 1.0    # g/L
Yxs    = 0.5    # gX/gS
Ypx    = 0.2    # gP/gX

# 2. Modelo. Assinatura obrigatória: f(t, y)
def batelada(t, y, mu_max, Ks, Yxs, Ypx):
    X, S, P = y
    mu = mu_max * S / (Ks + S)          # Monod, 1/h
    dXdt = mu * X                        # g/(L·h)
    dSdt = -dXdt / Yxs                   # negativo: substrato é consumido
    dPdt = Ypx * dXdt
    return [dXdt, dSdt, dPdt]

# 3. Condições iniciais e janela — na MESMA unidade de tempo dos parâmetros
y0 = [0.1, 20.0, 0.0]                    # X, S, P em g/L
t_span = (0.0, 24.0)                     # h
t_eval = np.linspace(*t_span, 300)       # onde queremos a saída

# 4. Integração
sol = solve_ivp(
    batelada, t_span, y0,
    t_eval=t_eval,
    args=(mu_max, Ks, Yxs, Ypx),
    method="RK45",
    rtol=1e-8, atol=1e-10,
)

# 5. Nunca confie sem checar
assert sol.success, sol.message

# 6. Gráfico com eixos rotulados e unidade
plt.plot(sol.t, sol.y[0], label="Biomassa X")
plt.plot(sol.t, sol.y[1], "--", label="Substrato S")
plt.plot(sol.t, sol.y[2], ":", label="Produto P")
plt.xlabel("Tempo (h)")
plt.ylabel("Concentração (g/L)")
plt.legend()
plt.tight_layout()
plt.show()

Assinatura

solve_ivp(fun, t_span, y0, method="RK45", t_eval=None, dense_output=False, events=None, args=None, **options)
  • fun(t, y) — tempo primeiro. O antigo odeint usa f(y, t): inverter é erro silencioso, porque o código roda e devolve lixo.
  • t_span — tupla (t0, tf), não um vetor.
  • y0 — vetor de condições iniciais, na ordem em que você desempacota dentro de fun.
  • args — parâmetros extras passados a fun. Preferível a variáveis globais.
  • t_eval — onde a saída é interpolada, não o passo de integração.

Escolha de método

MétodoTipoQuando usar
RK45explícitoPadrão. Resolve quase toda fermentação não rígida.
DOP853explícitoQuando precisa de precisão alta e o sistema não é rígido.
RadauimplícitoSistema rígido. Robusto.
BDFimplícitoSistema rígido, especialmente de ordem maior.
LSODAadaptativoAlterna sozinho entre rígido e não rígido. Bom quando você não sabe.

Rigidez aparece quando o sistema tem constantes de tempo muito diferentes — crescimento em horas e um passo metabólico em segundos. O sintoma é o integrador ficar lentíssimo, dar passos minúsculos ou falhar. A cura é método implícito, não tolerância mais frouxa.

Tolerâncias

erro_aceito ≈ rtol · |y| + atol

Padrões do SciPy: rtol=1e-3, atol=1e-6. São frouxos demais para fermentação, onde X começa em 0,1 g/L e S está em 20 g/L — a mesma tolerância absoluta é grosseira para um e fina para o outro. Use rtol=1e-8, atol=1e-10 como ponto de partida.

Teste de sanidade que vale o esforço: rode com tolerância apertada e com tolerância frouxa. Se as curvas diferem visivelmente, o resultado é do integrador, não do modelo.

Eventos

Para responder "quando o substrato acaba?" sem procurar no vetor.

def substrato_esgotado(t, y, *args):
    return y[1] - 0.01        # cruza zero quando S = 0,01 g/L

substrato_esgotado.terminal = True    # para a integração aqui
substrato_esgotado.direction = -1     # só quando S está caindo

sol = solve_ivp(batelada, t_span, y0, args=(...),
                events=substrato_esgotado)

print(sol.t_events[0])        # instante do cruzamento, em h

O evento é uma função escalar cujo zero é procurado. terminal=True encerra a integração; direction=-1 só dispara em cruzamento descendente.

Armadilhas

  • t_eval não é passo. O passo é adaptativo e interno. Uma transição abrupta pode ficar suavizada no gráfico se t_eval for esparso — a curva mente sem o integrador errar.
  • Ordem trocada em fun. f(y, t) em vez de f(t, y). Roda, não avisa, entrega curva errada.
  • Unidades misturadas. Parâmetros em h e t_span em min: a simulação "não sai do lugar". Erro de unidade mais frequente em código.
  • Condição inicial degenerada. X0 = 0 dá reta plana — é ponto fixo, não bug. S0 = 0 idem.
  • Concentração negativa. S levemente abaixo de zero no fim da batelada é artefato. Aperte a tolerância ou proteja: S = max(S, 0) dentro do modelo.
  • Divisão por zero em Monod quando Ks = 0 e S = 0. Ks nunca deve ser zero.
  • sol.success ignorado. Plotar sem checar é plotar uma integração que pode ter abortado no meio.
  • sol.y transposto. É (n_vars, n_t): sol.y[0] é a série de X, não o estado no instante 0.

Escalas muito diferentes no gráfico

Quando S está em 100 g/L e X em 1 g/L, a curva de X vira uma linha rente ao eixo. Duas saídas honestas:

# Eixo secundário
fig, ax1 = plt.subplots()
ax1.plot(sol.t, sol.y[1], "--", color="tab:orange", label="S")
ax1.set_xlabel("Tempo (h)")
ax1.set_ylabel("Substrato S (g/L)")

ax2 = ax1.twinx()
ax2.plot(sol.t, sol.y[0], color="tab:blue", label="X")
ax2.set_ylabel("Biomassa X (g/L)")

A outra é escala logarítmica no eixo y (ax.set_yscale("log")), que também deixa a fase exponencial virar reta — útil para estimar μ visualmente.
